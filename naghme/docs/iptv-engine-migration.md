# بررسی مهاجرت موتور IPTV نغمه به Media3 + LibVLC

این سند مربوط به شاخه آزمایشی `naghme/media3-libvlc-experiment` است. شاخه از commit
`77785469edfcd7b75277aac634bec0c90b9c9363` ساخته شده و شاخه اصلی تغییر نکرده است.

## وضعیت فعلی در commit پایه

- `native/android/NaghmeVideoPlayerPlugin.kt` موتور IPTV را با AndroidX Media3 / ExoPlayer پیاده‌سازی می‌کند.
- `scripts/setup-android.js` پلاگین بومی را کپی و وابستگی‌های Media3 را با نسخه 1.2.1 به `android/app/build.gradle` اضافه می‌کند.
- ماژول‌های فعلی: `media3-exoplayer`, `media3-exoplayer-hls`, `media3-exoplayer-dash`, `media3-ui`.
- `MainActivity.java` سه پلاگین Storage، VideoPlayer و LibraryVideoPlayer را ثبت می‌کند.
- پروژه Capacitor 6.2.x است و اسکریپت setup مقادیر minSdk=23، targetSdk=34 و compileSdk حداقل 34 را اعمال می‌کند.
- پوشه `android/` در مخزن نگهداری نمی‌شود؛ GitHub Actions آن را در هر اجرا با `npx cap add android` تولید می‌کند.
- workflow ساخت APK از Gradle 8.2.1 و JDK 17 استفاده می‌کند.

## تصمیم معماری

Media3 موتور پیش‌فرض باقی می‌ماند. LibVLC فقط به‌عنوان موتور جایگزین Android اضافه می‌شود؛ نسخه وب همچنان از مسیر پخش وب خود استفاده می‌کند. هیچ‌یک از این موتورها محدودیت دسترسی شبکه، احراز هویت، اشتراک یا مجوز ناشر را دور نمی‌زند.

## مواردی که پیش از ادغام کد LibVLC باید حل شوند

1. رابط فعلی JavaScript به نام `NaghmeVideoPlayer` شامل play/stop/pause/resume، زمان، صدا، روشنایی، کیفیت، bounds، fullscreen، قفل لمس و رویدادهاست. fallback باید همین قرارداد را حفظ کند یا انتخاب موتور در لایه JavaScript به‌صورت صریح مدیریت شود.
2. LibVLC باید lifecycle ویدئو، سطح نمایش، توقف و آزادسازی منابع را بدون تداخل با Media3 مدیریت کند.
3. وابستگی LibVLC Android AAR حجیم است؛ حجم واقعی APK باید در CI اندازه‌گیری شود. اندازه AAR به‌تنهایی معادل افزایش حجم APK نیست.
4. ABIهای هدف باید با دستگاه‌های مورد پشتیبانی پروژه مشخص شوند؛ محدودکردن ABI بدون دانستن دامنه دستگاه‌ها می‌تواند نصب روی برخی گوشی‌ها را ناممکن کند.
5. نسخه Kotlin، Android Gradle Plugin، Gradle و compileSdk نهایی باید از فایل‌های تولیدشده در workflow بررسی شوند؛ این فایل‌ها در commit پایه وجود ندارند.
6. پس از پیاده‌سازی، CI باید APK را بسازد، وجود هر دو پلاگین را در DEX بررسی کند و حجم APK را گزارش کند.

## ترتیب اجرای آزمایشی

- مرحله A: ارتقای Media3 و افزودن ماژول‌های رسمی موردنیاز فقط پس از تأیید سازگاری با Gradle/AGP تولیدشده.
- مرحله B: افزودن پلاگین مستقل LibVLC برای Android.
- مرحله C: افزودن fallback محدود و قابل‌ردیابی؛ ابتدا خطای واقعی Media3 ثبت شود، سپس کاربر/سیاست پخش اجازه دهد موتور جایگزین اجرا شود.
- مرحله D: آزمون CI و اندازه‌گیری APK؛ تا پیش از موفقیت این مرحله، این شاخه برای انتشار تولیدی آماده محسوب نمی‌شود.

## وضعیت آزمون

در زمان تهیه این گزارش، فقط سورس و workflow بررسی شده‌اند. هنوز تغییر وابستگی یا کد موتور انجام نشده و APK جدیدی ساخته نشده است.
