# فهرست اصلاحات v2 (نسبت به v1)
شماره‌ی خط‌ها مربوط به `app.js` نسخه‌ی ۱ است (نسخه‌ی پشتیبان: `naghme-v1-backup`).

## اشکالات یافت‌شده و رفع‌شده
| # | مشکل (نسخه‌ی ۱) | رفع |
|---|---|---|
| ۱ | **دکمه‌ی افزودن** (خط ۱۶۵، `$('#add').onclick`): در کتابخانه‌ی خالی هم دکمه‌ی داخل صفحه را کلیک می‌کرد و هم پنجره‌ی انتخاب را باز می‌کرد؛ نتیجه‌ی کلیک دوم روی پس‌زمینه‌ی پنجره، بسته‌شدن ناخواسته بود | تابع واحد `openAdd()`؛ کلیک پس‌زمینه در ۰٫۵ ثانیه‌ی اول نادیده گرفته می‌شود؛ `once()` برای جلوگیری از دوبار کلیک؛ ریست `input.value` پیش از هر انتخاب؛ جلوگیری از اجرای دوباره‌ی یک انتخاب و از اسکن هم‌زمان؛ لغو انتخاب بدون خطا |
| ۲ | **کاور MP3** (`readTags` خط ۲۳): فقط یک APIC، بدون unsynchronisation، extended header، ID3v2.2، data-length-indicator، اولویت نوع تصویر و اعتبارسنجی امضای تصویر؛ MIME نادرست حفظ می‌شد | فایل جدید `tags.js` با پوشش همه‌ی این موارد + ID3v1؛ تشخیص نوع از امضای واقعی تصویر؛ تصویر خراب = بدون کاور، نه خطا |
| ۳ | **ذخیره‌ی کاور**: Blob کامل در رکورد هر آهنگ؛ تکرار برای هر آهنگ آلبوم | مخزن `covers` (IndexedDB نسخه‌ی ۲) با شناسه‌ی محتوا؛ کاور یکسان فقط یک‌بار؛ مهاجرت خودکار داده‌های نسخه‌ی ۱ |
| ۴ | **بازیابی زمان پخش** (خط ۶۹ `onloadedmetadata`, خط ۱۷۱ boot): `S.resumeT` بدون بررسی شناسه روی هر آهنگی که بعد بارگذاری می‌شد اعمال می‌شد؛ حذف آهنگ‌های ناموجود اندیس صف را جابه‌جا می‌کرد | `S.resume={id,t}`؛ اعمال فقط وقتی شناسه، metadata و مدت معتبرند؛ پاک‌شدن با هر تغییر آهنگ؛ `S.pos` جدا برای ذخیره؛ اندیس بر پایه‌ی شناسه پیدا می‌شود |
| ۵ | **آهنگ‌های محبوب هنرمند** (خط ۷۷ `row`، `S.list`): اندیس ردیف‌ها نسبت به فهرست دیگری بود و آهنگ اشتباه پخش می‌شد | کلیک با `data-id` و بافت `data-ctx` (`main`/`pop`)؛ در صفحه‌های هنرمند، آلبوم، جست‌وجو، پوشه، فهرست‌ها یکسان |
| ۶ | حذف آهنگ جاری از صف (خط ۱۴۵ `qrm`) پخش را رها می‌کرد | بارگذاری آهنگ بعدی یا پاک‌سازی صف |
| ۷ | پرتره‌ی هنرمند بدون عکس، کاور یک آلبوم را نشان می‌داد | جایگزین زیبا با حرف اول نام؛ هرگز کاور آلبوم نیست |
| ۸ | کاور آلبوم از اولین آهنگ (شاید بدون کاور) گرفته می‌شد | `anyCov()` |
| ۹ | پوشه‌ها ترتیب نداشتند | ترتیب طبیعی بر اساس نام فایل |

## قابلیت‌های جدید
- اسکن: شمارنده‌ی جدید/خراب/قبلاً موجود/ردشده/خطا، درصد واقعی، توقف، **ادامه** و شروع مجدد، هم‌زمانی قابل تنظیم، خطای هر فایل جداگانه مهار می‌شود، پیام کمبود فضا/حافظه، `navigator.storage.persist()`.
- **حفاظت از آرشیو**: پنجره‌ی تأیید پیش از افزودن (نام پوشه، تعداد، ردشده‌ها، هشدار پوشه‌ی Download)؛ فیلتر محافظ مسیر (قرآن/«حلیه المتقین»/ضبط/Voice… قابل ویرایش) و حداقل مدت؛ برنامه هرگز خودکار اسکن نمی‌کند.
- هش SHA-256 فقط برای فایل‌های هم‌اندازه و با ذخیره‌ی نتیجه.
- ذخیره‌ی آخرین صفحه، فیلتر و مرتب‌سازی.
- پشتیبان نسخه‌ی ۲ با کاورها (کنترل حجم)؛ بازیابی با پیش‌نمایش، **ادغام یا جایگزینی** با تأیید، اعتبارسنجی کامل پیش از هر نوشتن، پذیرش نسخه‌ی ۱.
- PWA: سرویس‌ورکر شبکه‌اول با کش آفلاین، به‌روزرسانی با تأیید کاربر (بدون نسخه‌ی قدیمی گیرکرده)، manifest با آیکون‌های any/maskable، پیام آفلاین، وضعیت پشتیبانی مرورگر در تنظیمات.
- آزادسازی Object URLها در هر رندر؛ تصویر خراب = جایگزین؛ ظاهر جایگزین گرادیانی؛ دسترس‌پذیری دکمه‌ها (aria-label)، اندازه‌ی لمسی ۴۰px.
- Media Session: seekbackward/seekforward و positionState؛ نبود API بدون خطا.
