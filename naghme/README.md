# نغمه | NAGHME MUSIC STUDIO — نسخه‌ی ۲٫۲٫۸
«تمام موسیقی‌های تو، در یک خانه» — پخش‌کننده و مدیر آرشیو موسیقی، آفلاین، بدون سرور، بدون حساب کاربری؛ HTML/CSS/JS خالص بدون CDN.

## نسخه‌ی ۲٫۲٫۸ — IPTV با پخش ثابت
در صفحه‌ی «تلویزیون»، ویدئو و کنترل‌ها و کادر جست‌وجو/دسته‌ها ثابت می‌مانند و فقط فهرست شبکه‌ها اسکرول می‌شود؛ انتخاب شبکه فقط منبع ویدئو را عوض می‌کند (عنصر `video` دوباره ساخته نمی‌شود). جزئیات، آزمون‌ها و محدودیت‌ها: `docs/تغییرات-نسخه-2.2.8.md`. آزمون جدید: `cd tests && PW=… FIX=/tmp/t node iptv.test.js` (ویدئوی آزمایشی: `FIX/tv/red.webm`، ساخته‌شده با ffmpeg/libvpx). *APK در محیط ساخت این نسخه ساخته نشد.*

## فایل‌ها
`index.html` · `style.css` · `app.js` (برنامه) · `tags.js` (تگ/کاور ID3) · `platform.js` (لایه‌ی وب/اندروید) · `sw.js` · `manifest.json` · `icon-*.png` · `capacitor.config.json` · `package.json` · `native/android/` (پلاگین بومی) · `scripts/` · `tests/` · `docs/`

## اجرا
نیاز به build یا npm نیست. پوشه را روی **HTTPS** یا **localhost** بگذارید (برای سرویس‌ورکر، نصب PWA و SHA-256 لازم است):
`python3 -m http.server 8765` ← در Chrome آدرس `http://localhost:8765` .
برای گوشی: پوشه را روی یک میزبان ایستای HTTPS (مثل Netlify/GitHub Pages) بگذارید. باز کردن مستقیم `index.html` با `file://` پخش را اجرا می‌کند ولی سرویس‌ورکر/نصب ندارد.

## نصب PWA روی Android
Chrome ← آدرس برنامه ← منوی ⋮ ← «Install app / افزودن به صفحه‌ی اصلی» (یا «تنظیمات ← نصب برنامه»). پس از نصب، مستقل و آفلاین اجرا می‌شود. *(روی گوشی واقعی آزمایش نشده است.)*

## انتخاب آرشیو موسیقی
۱) «＋ افزودن» ← «انتخاب پوشه» و پوشه‌ی `Music/آرشیو موسیقی` را انتخاب کنید (زیرپوشه‌ها شامل می‌شوند). ۲) اگر Chrome گوشی شما انتخاب پوشه را پشتیبانی نکرد: «انتخاب چند فایل» ← همه‌ی آهنگ‌ها را انتخاب کنید. ۳) پنجره‌ی تأیید نام پوشه، تعداد فایل‌ها و فایل‌های ردشده را نشان می‌دهد؛ تأیید کنید.
- فقط همین انتخاب شما بررسی می‌شود؛ پوشه‌ی Download هرگز خودکار اسکن نمی‌شود.
- فایل‌های با مسیرِ شامل «حلیه المتقین»، قرآن، Voice، Recorder، ضبط، پیام صوتی… به‌صورت پیش‌فرض وارد نمی‌شوند (تنظیمات ← قابل ویرایش).
- فایل‌های شما هرگز تغییر نمی‌کنند و جابه‌جا/حذف نمی‌شوند.

## دسترسی به فایل بعد از بستن برنامه — کپی داخل برنامه
مرورگر اجازه‌ی دسترسی دائمی به پوشه‌ی گوشی را نمی‌دهد. راه‌حل نغمه: در پنجره‌ی تأیید افزودن، گزینه‌ی **«افزودن و کپی داخل برنامه»** را بزنید؛ آهنگ‌ها در حافظه‌ی IndexedDB برنامه ذخیره می‌شوند و **بعد از بستن مرورگر بدون انتخاب دوباره پخش می‌شوند (حتی آفلاین)**.
- هزینه: فضای اضافه‌ی حدود هم‌اندازه‌ی آرشیو (برای ۲٫۲ گیگابایت، ۲٫۲ گیگ). حجم و فضای آزاد مرورگر در همان پنجره نمایش داده می‌شود.
- Chrome ممکن است در کمبود فضا داده‌ی سایت را پاک کند مگر «ذخیره‌سازی پایدار» فعال باشد (برنامه درخواستش را می‌دهد؛ وضعیت در تنظیمات ← ذخیره‌سازی دیده می‌شود). اگر پاک شد، فقط با انتخاب دوباره‌ی پوشه برمی‌گردد.
- «افزودن بدون کپی» حجم کم دارد ولی بعد از بستن مرورگر باید دوباره پوشه را انتخاب کنید (اطلاعات می‌ماند، چیزی تکرار نمی‌شود).
- تنظیمات ← «حذف فایل‌های کپی‌شده» فضا را آزاد می‌کند؛ فایل‌های اصلی هیچ‌گاه دست‌نخورده می‌مانند.
- نسخه‌ی کپی‌شده در پشتیبان JSON نیست.

## آهنگ آنلاین (لینک مستقیم)
«＋ افزودن» ← «افزودن از لینک آنلاین…» ← آدرس مستقیم فایل صوتی (هر لینک در یک خط). برنامه مدت آهنگ را می‌سنجد و اگر سرور CORS و Range را اجازه دهد، تگ و کاور را هم می‌خواند؛ وگرنه فقط نام فایل. لینک‌ها در پشتیبان JSON هستند.
- فقط لینک مستقیم فایل صوتی (یوتیوب/اسپاتیفای و… پشتیبانی نمی‌شود).
- لینک `http://` روی سایت `https://` توسط مرورگر مسدود می‌شود؛ از `https://` استفاده کنید.
- **اکولایزر روی لینک‌های آنلاین اعمال نمی‌شود** (مرورگر در حالت CORS صدا را بی‌صدا می‌کند)؛ پخش عادی کار می‌کند. بدون اینترنت این آهنگ‌ها پخش نمی‌شوند.

## تصاویر
- **کاور آلبوم**: از تگ MP3 (APIC) خوانده، به ۳۰۰px کوچک و در مخزن `covers` ذخیره می‌شود (کاور یکسان یک‌بار). آهنگ بی‌کاور تصویر جایگزین دارد.
- **عکس هنرمند**: صفحه‌ی هنرمند ← «انتخاب تصویر» ← از گوشی؛ در IndexedDB ذخیره می‌شود، مستقل از کاور آلبوم، و در همه‌ی صفحه‌های آن هنرمند دیده می‌شود. «حذف تصویر» هم هست.

## پشتیبان‌گیری
تنظیمات ← «خروجی JSON»: آهنگ‌ها/هنرمندان/آلبوم‌ها (از اطلاعات آهنگ‌ها)، فهرست‌ها، علاقه‌مندی‌ها، تعداد پخش، تصاویر هنرمندان، کاورها، تنظیمات. **فایل‌های صوتی اصلی در پشتیبان نیستند.** «بازیابی»: ابتدا اعتبارسنجی، سپس انتخاب ادغام یا جایگزینی با تأیید.

## محدودیت‌های شناخته‌شده
تگ و کاور فقط MP3 (ID3v1/v2.2/v2.3/v2.4)؛ فرمت‌های دیگر پخش می‌شوند (در صورت پشتیبانی مرورگر) ولی نام/هنرمند از مسیر می‌آید. ویرایش تگ، تغییرنام/انتقال/حذف فایل، خروجی ZIP و تقویم فعالیت وجود ندارد. فونت Vazirmatn همراه پروژه نیست (دسترسی به اینترنت نبود): فایل `Vazirmatn-Regular.woff2` را در `fonts/` بگذارید؛ در غیر این صورت Tahoma/فونت سیستم استفاده می‌شود. جزئیات: `docs/گزارش-آزمون.md`.

## انتشار نسخه‌ی جدید
مقدار `VERSION` در `sw.js` را تغییر دهید؛ کاربران پنجره‌ی «نسخه‌ی جدید آماده است» را می‌بینند.

`cd tests && python3 make-fixtures.py /tmp/t && FIX=/tmp/t node tags.test.js && node scripts.test.js && FIX=/tmp/t node browser.test.js && FIX=/tmp/t node native.test.js` (نیازمند ffmpeg، Node 22، playwright+Chromium و سرور روی پورت ۸۷۶۵ برای پوشه‌ی پروژه).

# نسخه‌ی اندروید (APK با Capacitor) — v2.2

**هدف:** حل مشکل «بعد از بستن برنامه باید آهنگ‌ها را دوباره معرفی کنم». در APK، دسترسی به پوشه با Storage Access Framework گرفته و با `takePersistableUriPermission()` **دائمی** می‌شود؛ بعد از بستن برنامه و حتی ریستارت گوشی، آهنگ‌ها خودکار وصل می‌مانند.

> ⚠ **وضعیت آزمون:** در محیطی که این نسخه ساخته شد Android SDK، Gradle و اینترنت (npm) نبود. پس **APK ساخته و روی گوشی آزمایش نشده است**. جاوااسکریپت و اسکریپت‌ها با Node/Chromium و یک پلاگین ساختگی آزمایش شده‌اند؛ کد جاوا فقط در برابر stubهای دست‌نویس کامپایل شده، نه Android SDK واقعی. جزئیات: `docs/گزارش-آزمون.md`.

## پیش‌نیازها
Node 18+ ، JDK 17 ، Android SDK 34 (Android Studio یا فقط command-line tools). `ANDROID_HOME` تنظیم باشد.

## ساخت APK (دیباگ)
```
npm install
npm run android:add          # فقط بار اول: web → cap add android → پلاگین/مجوزها/Gradle → sync
cd android && ./gradlew assembleDebug      # ویندوز: gradlew.bat assembleDebug
```
APK خروجی: `android/app/build/outputs/apk/debug/app-debug.apk`

دفعه‌های بعد (پس از تغییر فایل‌های وب): `npm run android:sync` سپس `cd android && ./gradlew assembleDebug`.
اگر `^6.2.0` در npm پیدا نشد، نسخه‌ی ۶ موجود را در `package.json` بگذارید (نسخه‌ها آنجا آزمایش نشدند).

### بدون کامپیوتر: ساخت روی GitHub Actions
فایل workflow در ZIP از قبل در مسیر درست `.github/workflows/naghme-android.yml` (کنار پوشه‌ی `naghme/`، در ریشه‌ی مخزن) قرار دارد. از تب Actions اجرایش کنید؛ APK به‌صورت artifact دانلود می‌شود.

## نصب روی گوشی
فایل APK را روی گوشی بریزید و باز کنید (اجازه‌ی «نصب از منبع ناشناس») یا با `adb install app-debug.apk`.

## انتخاب آرشیو در APK
«＋ افزودن» ← **«انتخاب پوشه (دسترسی دائمی)»** ← پوشه‌ی `Music/آرشیو موسیقی` ← «استفاده از این پوشه/اجازه». یک‌بار کافی است. در تنظیمات بخش «پوشه‌های دائمی» هست: «اسکن مجدد» آهنگ‌های جدید را می‌گیرد و «حذف دسترسی» مجوز را پس می‌دهد.
- از اندروید ۱۱ به بعد خودِ پوشه‌ی **Download** یا ریشه‌ی حافظه قابل انتخاب نیست؛ یک **زیرپوشه** (مثل Music/…) انتخاب کنید.
- «کپی داخل برنامه» و «افزودن از لینک» بدون تغییر کار می‌کنند.

## انتقال از نسخه‌ی PWA به APK
داده‌های PWA (IndexedDB) با APK مشترک نیستند (مبدأ متفاوت). در PWA: تنظیمات ← «خروجی JSON»؛ در APK: «بازیابی» ← «ادغام»؛ سپس **همان پوشه** را انتخاب کنید. آهنگ‌ها (با همان نام پوشه‌ی ریشه) بدون تکرار به فایل وصل می‌شوند و علاقه‌مندی‌ها/فهرست‌ها می‌مانند.

## نحوه‌ی کار
`platform.js` تشخیص می‌دهد داخل Capacitor هست یا نه. در وب هیچ‌چیز عوض نمی‌شود. در اندروید پلاگین `NaghmeStorage` (`native/android/NaghmeStoragePlugin.java`) پوشه را می‌گیرد، فایل‌ها را فهرست می‌کند و تکه‌تکه (۱ مگابایت، Base64) می‌خواند؛ `tags.js` همان تگ/کاور را می‌خواند و مدت آهنگ با `MediaMetadataRetriever` می‌آید. برای پخش، فایل به Blob تبدیل و با `blob:` URL پخش می‌شود. هیچ فایلی نوشته/حذف/جابه‌جا نمی‌شود.

## محدودیت‌های شناخته‌شده APK
- **پخش در پس‌زمینه و کنترل صفحه‌ی قفل: تضمین نمی‌شود.** WebView برخلاف Chrome اعلان رسانه نمی‌دهد و ممکن است با رفتن برنامه به پس‌زمینه صدا را قطع کند. `MainActivity` عمداً حداقلی است (فقط ثبت پلاگین). راه‌حل کامل (Foreground Service + MediaSession) ساخته نشده است؛ روی گوشی واقعی بررسی کنید.
- **مجوز زمان اجرا:** SAF به `READ_EXTERNAL_STORAGE`/`READ_MEDIA_AUDIO` نیاز ندارد. این دو در مانیفست هستند (طبق درخواست) ولی استفاده نمی‌شوند و عمداً پنجره‌ی درخواست مجوز زمان اجرا نساخته‌ام تا پیام اضافه نیاید.
- هر آهنگ هنگام پخش کامل در حافظه بارگذاری می‌شود؛ فایل‌های خیلی بزرگ (مثلاً FLAC صدمگابایتی) کند یا سنگین‌اند.
- تگ و کاور فقط برای MP3 (ID3). فقط APK **دیباگ**؛ نسخه‌ی release/امضا و Play Store ساخته نشده است.
- مجوزهای دائمی Android محدودیت تعداد دارند (برای انتخاب پوشه مشکلی نیست؛ انتخاب «چند فایل» جداگانه هر فایل یک مجوز مصرف می‌کند).


## عیب‌یابی خطاهای رایج بیلد
| خطا | علت | رفع |
|---|---|---|
| `Cannot read properties of null (reading 'pickDirectory')` | دو علت جدا: (۱) **سمت جاوااسکریپت:** در WebView بدون bundler ممکن است `Capacitor.registerPlugin` اصلاً تعریف نشده باشد (آن تابع از جاوااسکریپت `@capacitor/core` می‌آید) و کدی که فقط با آن پلاگین را بگیرد `null` می‌ماند؛ (۲) **سمت جاوا:** پلاگین در `MainActivity` ثبت نشده یا `registerPlugin` بعد از `super.onCreate` است یا APK قدیمی نصب شده | `platform.js` (v2.2.2) پلاگین را به سه روش پیدا می‌کند: `Capacitor.Plugins.NaghmeStorage` ← `registerPlugin` ← `Capacitor.nativePromise`، و `null` نمی‌ماند. اگر هیچ‌کدام نبود، خودکار صفحه‌ی **«تشخیص پلاگین بومی»** باز می‌شود (همچنین از تنظیمات). `MainActivity` پلاگین را قبل از `super.onCreate` ثبت می‌کند و `setup-android.js` ترتیب و `namespace` را کنترل می‌کند |
| `cannot find symbol FilePickerPlugin` | باقی‌مانده‌ی تلاش‌های قبلی (پوشه‌ی `android/` یا `package.json` قدیمی) هنوز به `@capawesome/capacitor-file-picker` اشاره می‌کند | این پروژه به آن وابسته نیست. پوشه‌ی `android/` قدیمی را پاک کنید (`rm -rf android`)؛ workflow هر بار آن را پاک و از نو می‌سازد، و `setup-android.js` هر باقی‌مانده‌ی FilePicker را پیدا و متوقف می‌کند |
| `Invalid workflow file: Unexpected value 'path'` | `path:` در جای نادرست (باید فقط زیر `with:` یا `paths:` زیر `push:` باشد) یا تورفتگی اشتباه | از فایل `.github/workflows/naghme-android.yml` همین ZIP بدون ویرایش استفاده کنید؛ ساختارش با `tests/workflow.test.py` بررسی شده |

### نصب از Termux (یک دستور)
ZIP را باز کنید (پوشه‌ی `naghme-final` شامل `.github/` و `naghme/` است) و:
```
cd ~/diyar-widgets/diyar-widgets && rm -rf naghme && cp -r /مسیر/naghme-final/. .
git add -A && git commit -m "naghme v2.2.3" && git push
```
اگر توکن شما دسترسی `workflow` ندارد، پوش فایل `.yml` رد می‌شود؛ در این حالت فقط `naghme-android.yml` را یک‌بار از طریق وب گیت‌هاب در `.github/workflows/` آپلود کنید (اگر محتوای فایل با نسخه‌ی موجود در مخزن یکی باشد، گیت آن را تغییر‌یافته نمی‌بیند و پوش مشکلی ندارد).
سپس در گیت‌هاب: Actions ← naghme-android ← Run workflow. خروجی: artifact با نام `naghme-debug-apk`. (پوشه‌ی `naghme/` در مخزن باید کاملاً با محتوای این ZIP جایگزین شده باشد.)

### خواندن صفحه‌ی «تشخیص پلاگین بومی»
تنظیمات ← «تشخیص پلاگین بومی» (یا خودکار هنگام خطا). از آن اسکرین‌شات بفرستید:
- **«NaghmeStorage در PluginHeaders: ✗»** یعنی سمت جاوا ثبت نشده: `MainActivity` اشتباه است یا APK قدیمی نصب شده (نسخه‌ی وب داخل APK را با `package.json` مقایسه کنید).
- **✓ ولی ping خطا دارد** یعنی پلاگین ثبت شده ولی اجرای متد خطا می‌دهد؛ متن خطا همان‌جا نوشته می‌شود.
- **همه ✓** یعنی پلاگین سالم است و مشکل جای دیگری است.

workflow پیش از آپلود APK بررسی می‌کند که `NaghmeStoragePlugin` و `MainActivity` واقعاً داخل `classes*.dex` و `platform.js` و `build-info.json` جدید داخل `assets/public` باشند؛ اگر نباشند، بیلد با خطا متوقف می‌شود.
